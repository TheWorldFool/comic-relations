# 详细使用与实现说明

[返回项目首页](../README.md) · [English overview](../README.en.md)


一个本地运行的漫画阅读工作台。React + TypeScript 前端，Express 服务端，DeepSeek 视觉 API 顺序阅读图片，Sharp 从原图裁剪人物头像。一般互动更新当前图，仅重大关系转折新增阶段。没有预置漫画、演示人物或虚构关系。

## 运行

需要 Node.js 22.12+（本项目在 Node.js 24 上验证）。

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

浏览器打开 **http://127.0.0.1:3001**。开发时运行 `npm.cmd run dev`，打开 http://127.0.0.1:5173。

复制 `.env.example` 为 `.env`，配置 `DEEPSEEK_API_KEY`，或用 `DEEPSEEK_API_KEY_FILE` 指向只包含密钥的 UTF-8 文件。也可以在界面的“阅读设置”填写。模型默认 `deepseek-flash`，API 地址和模型名均可修改。图像输入格式依据 [DeepSeek 官方视觉文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

源码和示例配置不含密钥。界面保存配置后优先使用 `data/settings.json`，API 不向前端返回密钥。修改 API 地址后需重新提供密钥，不会把旧密钥自动转发给新地址。测试图片连接会产生少量模型用量。

模型生成上限默认 32768 tokens，可通过 `DEEPSEEK_MAX_TOKENS` 修改。对 `deepseek-flash` / `deepseek-v4-pro` 显式使用 `low` 思考强度（可用 `DEEPSEEK_REASONING_EFFORT=low/high/max/none` 配置），避免继承接口默认的高强度思考。依据：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 与 [API 参数说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

如果返回 `finish_reason=length`，不保存半截结果；保留原图与前文上下文，关闭上述支持模型的思考模式，自动重新请求一次完整 JSON，仍遵守配置的 token 上限。初读最多两轮内容生成，格式修正和截断恢复共用这一上限。每轮请求遇到 408、429、500、502、503、504 或明确的临时网络错误时，最多再重试两次（初读最坏共 6 次 HTTP 请求，身份复核另计），实际次数计入用量记录。不无限重试、不拼接残缺 JSON。连续失败停在当前页，已完成页面保留。截断诊断保存请求预算、结束原因、文本长度及可用的 token 用量，不保存推理正文、密钥或图片。上下文省去重复历史账本与基线证据，但保留当前档案、状态、关系、阶段基线和累计记忆。自定义模型不注入专用思考参数。

## 使用

1. 导入一组图片或整个文件夹。支持 JPG、PNG、WebP、GIF（静态首帧），单张最大 32 MB、单次最多 1000 张。文件夹保留相对路径用于排序，如 `第2话/001.jpg` 排在 `第10话/001.jpg` 前面。追加导入排在已有页面之后，可点击排序按钮重新统一排序。
2. 在左侧拖动页面，或用上下箭头修正顺序。选择分格从右到左或从左到右。页序与漫画内部的分格方向分别处理。
3. 在“阅读前准备”中多选缩略图、按页码范围选取，批量设为正文、封面、广告或附页，也可主动将剩余未划分页设为正文。所有页都确认后才能开始，后端同样强制校验。追加页面需重新确认新增部分；确认旧页原有用途不会清空既有进度。
4. 保存划分后默认自动识别作品并联网查背景，可核对来源后采用，或不采用新背景直接开始。也可以仅保存划分。正文按页发送至模型，广告和附页排除；阅读范围内已划分的封面最多取首张和最近一张，明确标注为身份参考，也可作为背景识别素材。封面不作为正文事件或关系证据。页面用途由用户确定，模型不会重新判定页面用途，也不因自己的分类把握而暂停；内容拒绝与真正的接口/格式错误仍会暂停。每页完成立即保存，失败后从未完成页继续。
5. 点击关系阶段查看历史图谱，每个阶段显示原导入顺序中的页码范围；漫画明确提供章节或故事时间时一并显示。点击人物查看外貌身份、关系证据及证据页，拖动人物、缩放画布，或切换到“关系工作台”与独立标签页。宽屏详情侧栏可收起，窄屏切换查看，人物档案支持姓名、别名及外观搜索。
6. 自动头像由模型提供位置、服务端从原图裁剪。头像不准确时，点击人物，再选择“从当前页框选头像”，在原图框选后保存。
7. 关系图右上角下载按钮导出整个项目分析 JSON（含页面范围、人物、关系证据及历史阶段；图片仍存本机）。

模型格式偶发异常时先尝试明确、无歧义的本地语法修复（例如对象末尾无值的空字段），仍不合格再自动纠错一次（最多两轮内容生成，临时网络错误的有限重试另计）。未知时间、空别名及无效的可选头像框可兼容处理；剧情记忆、人物列表、关系变化等关键字段不会用空值代替。纠错仍失败时停在当前页并显示具体字段，已读进度保留。原始异常输出、校验问题和纠错结果保存在对应项目的 `diagnostics/<page-id>.json`，仅留本机、不通过静态文件接口公开，便于定位问题；文件不含 API 密钥或图片请求。

提示词要求客观分析完整剧情，而不是忽略成人情节。对于明确成年人的情节，在允许范围内概括事件事实、意愿证据、动机、后果及关系影响，不因裸露或成人主题直接当作无剧情页面。表达保持分析性、非色情化，不复述露骨过程；性接触不自动等于恋爱、自愿或长期承诺，动作细节不成为关系标签。模型的内容拒绝、`content_filter` 或明确 `blocked` 返回会单独标记为“内容无法处理”并暂停，不触发格式纠错、不伪装成封面广告，也不通过指定正文绕过限制。涉及未成年人或疑似未成年人的性内容不会继续提取；不保证第三方模型会接受所有成年题材页面。

前端在暂停和出错状态也会同步后台进度，切回窗口立即刷新，不再因为旧报错停止状态更新。

阅读暂停或因错误中断时，工作台上方提供“继续分析”入口，从当前待处理页续读，已完成页不会重读。内容无法处理的页面会保留拒绝原因，需先将其排除才会继续。模型接口或格式错误会保留具体错误信息，修正后可直接重试。临时接口错误先有限退避重试；遵循不超过 15 秒的 Retry-After，服务要求等待更久时保留错误供稍后继续。密钥、余额、配置错误及内容拒绝不进行网络自动重试，暂停会取消退避等待。

仅调整未读页面的顺序保留既有记忆、人物、阶段和进度；更改已阅读页面的顺序、分格方向或用途会使前文理解失效，因此清除原分析后重新阅读；界面会提示。移除尚未阅读的页面不影响已完成的分析，会保留进度。用户导入的源文件不被修改。

## 阅读速度与连续性

旧人物采用增量输出：模型仍列出本页所有实际出场人物，但已知 ID 的 `name`、`aliases`、`description`、`nameType` 没有变化时可以省略，由系统从已有档案补回。只按现有 ID 或已确认的 ID 重定向查找，不根据姓名相似或 `sameAs` 提议借用别人的档案。新人物必须提供必要资料，显式错误字段仍会触发校验。头像框、服装、发型和本页外貌观察不从历史自动补回。复核请求标明哪些字段来自旧档案，避免将它们当作本页新证据；旧版完整输出仍兼容。

身份复核由系统选择对象：新人、重新登场、姓名/别名/身份资料变化、明确疑点仍检查；待定人物和定期复查机制保留。对近期核对过、持续出场且无身份变化的已确认人物，纯关系转折不再触发全员复核；转折伴随该人物状态或档案更新时仍复核。人工核对过的具体出场可以接续短期复核间隔，但文本档案固定不等于确认后续画面身份，也不会永久跳过复核。判断前页出场优先使用已校正的出场记录，避免旧摘要中的误归属反复触发检查。

身份复核将多人共享的历史场景按页码集中发送一次，每个人的出场次数和身份依据仍独立保留，并通过页码引用完整梗概。单次模型请求内完全相同的图片也只发送一次，保留各人物对应的说明；不同裁图、分辨率和清晰度参数不会被折叠。未发现重复图片时不增加额外指令。这些优化减少重复输入，不修改已保存记录，也不并发分析未来页面。实际节省的时间仍取决于素材、模型推理与服务排队，输入缩减比例不等于耗时缩减比例。

普通正文页返回 `memoryMode: delta`，只输出本页新增剧情；长期摘要保存在 `project.memory`，摘要后的逐页增量和未解线索保存在 `project.readingMemory`。两部分共同构成前文，导出分析 JSON 时均保留。旧项目已有的 `memory` 直接作为长期摘要使用，不需要清空进度。

累计 5 个正文增量后的下一张正文要求 `checkpoint` 汇总；增量文字累计达到 6000 字符时也提前要求汇总。汇总整合旧摘要、全部增量和本页事件，成功后清空已整合的增量。空字符串或纯空白汇总会被拒绝，不能清空已有剧情；普通增量页无新增事件时仍允许空记忆。重要未解线索独立保存，只能通过模型明确的解决操作移除；没有在某页提及不会删除。广告、封面和附页不推进记忆汇总计数。记忆汇总不会产生新的关系阶段。

每页请求根据当前记忆计划生成对应的任务指令、输出示例和仅允许该模式的 JSON Schema；汇总页不会携带增量页模板，格式纠错和截断重试也沿用同一任务。新模型输出必须明确记忆模式并提供 `threadChanges`（没有变化时为 `[]`），防止将增量误当完整记忆覆盖前文。格式失败、错误线索引用和内容拒绝均不提交本页，继续分析从最后已保存状态恢复。内部旧格式读取逻辑仍兼容完整记忆，但新 API 请求强制使用明确的模式。

图片准备采用每个阅读任务独立、有界的内存缓存。请求第 N 页时并行准备其参考图和下一张正文图片；第 N+1 页的模型请求仍等待前页校验、应用并保存。预取不调用模型、不生成未来剧情上下文、不额外产生 API 用量，失败不会阻止当前页，取消或任务结束释放缓存。维持原有图片分辨率与质量。

每页计时在已有总耗时、请求数和 Token 用量基础上增加图片/上下文准备耗时、API 耗时、上下文字符数与图片数。界面显示前两项，后两项在项目 JSON 的 `pages[].timing` 中查看。准备耗时是当前页等待准备完成的时间，不包括已与上一页请求重叠的全部后台工作；API 耗时包括各次请求与响应处理。页面计时显示最近一次阅读；项目 readingRuns 账本累计每次成功、失败和取消的请求、用量和耗时，整页重试、删除页面或清除分析不删除账本。旧项目首次记录新调用、清除分析、排序或删除页面时迁移已有计时；旧版曾被覆盖的历史无法补回。服务未返回的 Token 用量无法精确获知。身份复核 API 耗时另记 identityReviewMs 并显示在页面计时中；复核失败也显示具体原因，旧数据没有分项时不推算。每次新调用另记录模型、端点域名、提示词哈希和推理配置，不记录密钥；界面显示累计耗时与请求数。

当前采用顺序剧情分析和并行图片准备，未启用多页模型请求并发或多页合批。已有的并发原型会使用尚未包含前页结果的快照，冲突记录不等于剧情理解正确，不能把其加速比视为正式版本保证。实际速度及身份连续性仍需同素材、同模型、同配置的多轮评测。

## 角色档案与状态

“背景与人物”可自动查找背景，也保留手动编辑。AI 从最多两张封面和前两张正文中选最多三张识别标题、署名与人物线索，再调用现有 DeepSeek 密钥对应的 Anthropic Web Search，最多三次搜索，优先官方资料与可靠百科。即使原作名未知，也会用独特章节标题等查询出处。只有无可用线索时留待用户补充；可填写名称线索后重试。

检索结果先保存为草稿，展示原作、识别依据、背景、人物对照与来源链接，用户采用后才进入阅读上下文。来源必须来自此次实际返回的 `web_search_tool_result`；已知跟踪参数与编码差异可规范化，仍不匹配时只自动校正一次，并从真实来源目录选择编号，不会把未联网回答或模型自编 URL 当搜索证据。无法搜索、缺乏来源或结果截断时保留旧背景。背景是原作参考，不直接写成本篇剧情，也不提前更新角色生死/关系。官方搜索能力说明：[DeepSeek Web Search](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/#using-web-search-in-claude-code)。联网检索会产生额外模型用量，自定义兼容服务需要提供相同搜索接口。

模型复用临时人物 ID，后续出现真名时更新原档案并保留旧称呼。额外身份复核按需触发：新人、明确改名或归属线索、身份疑点、重新登场、剧情转折时检查。连续稳定出场的已确认人物不每页追加调用，但距离上次复核到第 6 张正文会再次检查，避免旧 ID 永久免检。待定人物在没有新线索时，距离上次复核到第 3 张正文才重查，最后一张正文仍会检查；人工复核不受间隔限制。主阅读仍逐页接续前文，始终包含完整人物索引。复核从全部人物的姓名、别名和外观中检索候选，不局限于最近 8 人。候选排序目前采用文字特征相似度和明确身份线索，不是视觉向量检索，不能保证总能召回正确角色。

复核比较当前页、前一张正文、最多两张已划分封面及最多 12 张候选参考图。封面只提供外貌和明确姓名线索，不能据此创造正文关系，也不为仅出现在封面的人物创建正文档案。每人逐步积累最多 4 张参考图，保留首次样貌和后续不同角度；缺少可用头像时最多补取两张已读初登场页，仍受总图数上限约束。主阅读请求仍使用最近相关的最多 8 人头像及全部人物文字索引。只裁剪模型能够定位的画面，不凭空生成头像；旧项目参考图从后续阅读逐步积累。

匹配到另一身份需要复核返回至少两类具体依据（稳定视觉特征、连续动作/场景、明确对白指向），且没有反证；不再只凭初读的 sameAs 分数决定。证据不足时保留 identityState=pending 的出场档案；复核格式失败或临时接口失败时，新人和已有待定人物仍保留待定，已确认人物保留初读归属，并记录复核失败，不因技术故障凭空拆出重复档案。待定档案不阻断正常阅读，其人物和相关连线暂不进入正式阶段图。剧情、状态、关系及身份观察仍保存；待定人物后续确认身份时将已有证据归入对应人物。仅被提及的名字仍不生成出场档案。旧的明确正式档案不会被批量自动合并。本页误用了旧 ID 时，只修正本次出场及本页关系端点，不把两个历史档案合并；明确是另一位尚未建档的人物时，可以建立独立档案。不同明确姓名若要作为同一档案归并，必须额外提供别名、改名或译名对应依据；仅视觉相似不足以改名。

待定人物使用 confirm 确认独立身份，不会把它自己算成需要区分的其他人；多次出场历史供模型核对，次数本身不触发确认。一项复核字段损坏仅将该人物保留待定，不连带压低其他人的有效结论。兼容缺省空候选、空反证、单项对象及顶层决策数组，但不猜测缺失的身份依据；正文阅读仍要求顶层对象。复核状态、待定数量及失败原因记入 identityReviewResult，限流、截断、格式错误等不再统一隐藏为“证据不足”。

“背景与人物 → 待定身份”可查看参考图、候选与初登场页，人工选择对应人物或确认独立人物。已经产生的重复档案可在“人物归并”中选择人物，点击“AI 复核所选人物”获取建议，再由用户确认合并；该操作保留进度并单独累计用量，不覆盖页面原阅读计时。待定人物经 AI 再次复核确认独立后会更新当前图；不同已有档案的全局合并仍由用户确认。人工固定项会阻止待定档案自动并入他人，需要先人工核对。

身份复核最多一轮内容生成，网络临时错误仍按有限重试处理；不进行额外格式纠错。最坏情况下，初读两轮与身份复核一轮合计最多 9 次 HTTP 请求。身份复核实际请求计入 attempts，触发轮数另记 identityReviewRequests。复核拒绝处理的页面仍暂停且不提交，用户取消会终止等待。身份待定的历史阶段不补写后来才知道的姓名；确认后的当前阶段显示已归属的资料，证据保留原页码。

新版阅读还会把出场和身份分开存储：`appearances` 保存每页每个可见主体的一条代表性观察（页码、定位、裁图、当时外观、可选衣着/发型、证据与归属修改记录）。它不是完整的逐分镜检测器。同一人物在本页多个画格出现时，目前仍保留一条代表观察。模型沿用前文但未独立复核的出场标记为 continuity；身份未知时 characterId=null，临时索引在 pendingIdentities 中保存，继续阅读仍可复用其 trackId，不必创造正式人物。

“背景与人物校对 → 逐次出场”可按人物名、页码查找，勾选具体出场后绑定到已有确认人物、单独建档或设为待定。只改变所选记录，不默认合并其他出场；每次修改保留原始观察和归属历史。选中同一批记录再次绑定即可纠正先前操作。当前状态和关系根据关联出场的事件证据重算，包含关系解除、有向状态和仅提及人物的文本证据；人工固定项仍优先。已结束的历史阶段保留当时结论，当前阶段及其起点比较依据更新；不会重写过去阶段或剧情摘要。后续请求单独携带人工出场校正，避免旧摘要中的误称覆盖校正。

出场归属调整后，初登场页会按目前保留的出场重新计算，旧版基线中的更早记录仍予以保留。如果某个确认人物的出场全部转给他人，且没有独立文本证据、人工固定项或旧版基线支持，该人物从当前关系图隐藏，档案和修改记录继续保留，方便重新绑定。这不表示人物死亡或剧情退场，也不影响已结束的历史阶段。

新裁图首先存为出场证据，只有本次身份复核通过或用户明确核对后，才加入正式人物参考库。普通连续页不会用新裁图覆盖既有参考；AI 确认待定身份时，历史存疑裁图仍需各自核对，不能因为整组获得身份就全部升级为标准参考。用户明确确认整组独立身份会批准该组裁图；混有人物时应使用逐次出场校对。换装、临时发型另存于观察，未经复核不覆盖已确认档案的稳定外貌。

这层记录随原阅读响应生成，不增加一次模型调用；人工逐次校正和证据重算在本地完成。旧项目继续阅读时以已有结果为基线（identityBaseline），只从新读取的页面开始积累独立证据。旧页缺失的定位、裁图归属与事件记录不会补造，因此旧页仍使用原来的档案校正/归并功能。新事件的证据在 appearanceRelations、appearanceFacts 中保留；清除分析同时清除这些记录，累计 API 用量仍保留。

复核仍使用同一个模型，可能延续初读误判；多类依据校验不是经过校准的正确率保证。尚未加入漫画专用视觉重识别模型，也未完成跨作品准确率评估。

已有重复人物可在“人物归并”中选择重复档案与保留档案，预览后确认合并。同步更新关系端点、状态目标、别名、阶段图和基线，去掉自身连线；历史阶段只使用当时已有信息。后续模型通过重定向表沿用归并结果。最近一次合并保存本机私有备份，继续阅读或发生其他编辑前可撤销；有后续修改时拒绝覆盖新进度。不会自动批量合并已有项目，也不自动改写旧的逐页阶段。

点击人物卡片打开“角色档案”，或从该标签浏览本阶段全部角色。档案包含简介、别名、身份背景、当前状态和变化/线索记录，每条新事实均附证据与原始页码。图中展示最多两条状态摘要，点击人物可查看全部。

模型按作品选择档案与状态维度，支持生存、健康、行踪及对指定人物的好感、信任、敌意等。态度按人物方向分别记录；没有原作数值时不生成好感分数。未知状态留空，推测标记“待确认”，存疑反向线索保留在记录中，不覆盖已确认事实。相同状态不重复记入历史，明确撤销有记录可查。

一般状态变化更新当前阶段；主线人物明确死亡、复活等重大状态转折可在模型给出持久影响的依据且置信度不低于 0.85 时新增阶段。档案按阶段保存，早期阶段不显示后文状态。

旧项目自动展示已保存的姓名、简介、头像和关系；新结构化档案和状态从后续阅读开始积累，不将旧简介猜测成生死或好感，也不自动重读、清空进度。完整重读可使用现有“清除分析并重新阅读”，会产生 API 用量。

## 阶段规则

- 第一张正文建立初始阶段，此时可以没有关系。
- 以人物 ID、关系维度和方向定位关系；双向关系的端点顺序不影响比较。
- 小变化、新增关系或旁支人物只更新当前阶段的图、人物和结束页码，不单独建图。
- 新阶段必须同时满足：关系数据或已确认的重要状态确实变化，模型明确给出有持久影响的重大转折 `turningPoint`、具体理由和不低于 0.85 的置信度。模型默认返回 `turningPoint: null`，不确定时不切阶段；没有固定每几页分图的规则。
- 提示词使用当前阶段起点、初始关系和累计记忆，判断正式结盟、决裂、身份真相导致的关系重构等质变。证据补充、同义改写、同一场景的连续动作和短暂情绪不作为转折。
- 新阶段深拷贝人物和关系；已结束阶段展示该阶段末尾的状态，不被后文覆盖。当前阶段持续更新，起点关系单独保留以供模型比较。人工修正头像会同步到已有阶段。
- `kind` 是模型产生的稳定关系维度，`label` 是简短的稳定状态；详细事件写在证据和梗概中。阶段判断仍依赖模型语义判断，需要根据证据核对。
- 已有旧版逐页阶段不自动改写。新规则适用于后续阅读和新项目，历史数据保留。

- `server/identity-state.ts`：待定身份、参考图库与正式关系图过滤。
- `server/index.ts`：导入、裁剪、后台阅读任务和 API。

- `data/projects/<id>/`：本地持久化项目、图片、缩略图和头像；每页结果原子写入 `project.json`。

这是面向个人本机的核心版本，服务仅监听 `127.0.0.1`，不是带多用户认证的公网服务。模型判断可能有误，不能保证广告识别或跨页身份匹配百分之百正确；人工页面划分、证据核对和人物归并用于纠错。暂不支持 PDF、压缩包导入、OCR 独立校对或自动批量合并已有正式人物。

开发时可运行 `npm.cmd run test:live -- --checkpoint` 检查真实接口的记忆汇总协议：使用隔离的原创测试图和预设前文，检查首次响应即返回 `checkpoint`、汇总后清空待汇总记录并保留未解线索。会产生 API 用量，不读取或修改用户书架；不能代替真实漫画的理解质量评测。

## 人工校正、合并回退与备份

在“背景与人物 → 人工校正”中可修改姓名、别名、外貌，以及已有档案、状态和关系；支持撤销错误结论。保存后更新当前阶段；默认仅校正当前结论，后续剧情可以继续更新。选择“持续固定”才会阻止模型覆盖，直到手动解除；此前阶段保留原记录。固定按人物 ID、事实维度、关系端点与方向匹配，不能保证模型语义层面的所有同义改写都能自动识别，仍需人工核对。全量清除分析会清除固定项。

合并后的立即撤销仍要求没有后续修改。新合并记录另外支持“回到最近合并前”：即使后来继续阅读，也可以明确确认后恢复合并前的人物和阶段，后续页面需重新分析。当前结果另存本机备份，图片与累计阅读用量保留。只支持最近一次有记录的合并，且已读页顺序、用途和阅读方向不能变化；不自动猜测合并后哪些新事实该分给哪一人。旧合并记录不会自动迁移为可回退记录。

每次项目保存前，将上一次可读取的状态原子写入 project.backup.json；损坏的当前文件不会覆盖好备份。无法读取的项目仍在书架标明“读取失败”，有有效备份时可确认恢复；恢复前会保留当前原文件。没有备份时明确提示保留数据目录以便人工恢复。这是最近一次状态备份，不能代替独立数据备份。


人工固定期间，新阅读得到的档案、状态和关系证据仍会保存，“逐次出场”中可以展开查看本页档案与状态观察。解除事实或关系固定后，会在本地按已保存的证据重算当前结果并保留其他固定项，不额外请求模型；姓名等人物字段解除固定后允许后续阅读更新，不直接恢复旧称呼。旧版本未保存的证据无法自动恢复，没有出场账本的旧项目仍保留现值，需后续阅读或人工校正。


## 补录与校对工作流

主页会统计新旧结构中的待定人物、身份复核未完整完成的页面和缺少头像的人物。“分析完成”表示页面处理结束，不表示人物与剧情已全部核实。失败页提示保留当时的复核记录，不会因为后续人工确认就悄悄消失，也不能据此判断还剩多少真实错误。

在“背景与人物 → 逐次出场”展开“补录漏识别人物”，选择已分析的正文页，拖动框出人物，填写依据，绑定已有确认人物或新建独立档案。没有真名时使用临时外观称呼。补录生成独立出场、参考裁图并更新当前人物图，不调用模型；不支持在未读页、封面或被拒绝的页面建立正文出场。同页已有对应人物时应校正已有出场，避免重复补录。

在“人工校正”选择档案/状态或关系，再选择“补充遗漏记录”，可填写属性/关系类型、对象、内容、证据及页码。默认“仅校正当前结论”允许以后剧情变化；此类事实和关系校正作为人工事件保存，后续重算不会丢失。校正于当前已读进度生效，证据页可更早，但不会追溯改写已结束阶段。“持续固定”适合需要一直约束模型的结论；已有固定项需先解除，才能保存同一维度的一次性校正。旧版本/API 未传 scope 时仍采用持续固定，保持兼容。

在校对窗口点击出场或待定人物的页码，可打开旁边的原页对照，保留已选记录和未保存表单；“在阅读器打开”会离开校对窗口。切换校对标签仍可能重置对应表单，请先保存。

阅读时显示当前准备、剧情理解、输出修正、身份复核或保存步骤，以及本页已等待时间。平均耗时采用最近最多十张已完成正文页，剩余时间只是按此均值估算，不保证后续页的重试和复核耗时相同。

阅读位置和拖动后的各阶段人物位置保存在当前浏览器。切换项目、阶段或刷新后可恢复；“整理布局”重新自动排列并保存。不跨浏览器同步，不属于项目导出的分析数据。
