# 详细使用与实现说明

[返回项目首页](../README.md) · [English overview](../README.en.md)


一个本地运行的漫画阅读工作台。React + TypeScript 前端，Express 服务端，DeepSeek 视觉 API 顺序阅读图片，Sharp 从原图裁剪人物头像。一般互动更新当前图，仅重大关系转折新增阶段。没有预置漫画、演示人物或虚构关系。

## 运行

需要 Node.js 22.12+（本项目在 Node.js 24 上验证）。

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

浏览器打开 **http://127.0.0.1:3001**。开发时运行 `npm.cmd run dev`，打开 http://127.0.0.1:5173。

复制 `.env.example` 为 `.env`，配置 `DEEPSEEK_API_KEY`，或用 `DEEPSEEK_API_KEY_FILE` 指向只包含密钥的 UTF-8 文件。也可以在界面的“阅读设置”填写。模型默认 `deepseek-flash`，API 地址和模型名均可修改。图像输入格式依据 [DeepSeek 官方视觉文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

源码和示例配置不含密钥。界面保存配置后优先使用 `data/settings.json`，API 不向前端返回密钥。修改 API 地址后需重新提供密钥，不会把旧密钥自动转发给新地址。测试图片连接会产生少量模型用量。

模型生成上限默认 32768 tokens，可通过 `DEEPSEEK_MAX_TOKENS` 修改。对 `deepseek-flash` / `deepseek-v4-pro` 显式使用 `low` 思考强度（可用 `DEEPSEEK_REASONING_EFFORT=low/high/max/none` 配置），避免继承接口默认的高强度思考。依据：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 与 [API 参数说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

如果返回 `finish_reason=length`，不保存半截结果；保留原图与前文上下文，关闭上述支持模型的思考模式，自动重新请求一次完整 JSON，仍遵守配置的 token 上限。每轮阅读最多两次请求，格式修正和截断恢复共用这一上限，不无限重试、不拼接残缺 JSON。连续失败停在当前页，已完成页面保留。截断诊断保存请求预算、结束原因、文本长度及可用的 token 用量，不保存推理正文、密钥或图片。上下文省去重复历史账本与基线证据，但保留当前档案、状态、关系、阶段基线和累计记忆。自定义模型不注入专用思考参数。

## 使用

1. 导入一组图片或整个文件夹。支持 JPG、PNG、WebP、GIF（静态首帧），单张最大 32 MB、单次最多 1000 张。文件夹保留相对路径用于排序，如 `第2话/001.jpg` 排在 `第10话/001.jpg` 前面。追加导入排在已有页面之后，可点击排序按钮重新统一排序。
2. 在左侧拖动页面，或用上下箭头修正顺序。选择分格从右到左或从左到右。页序与漫画内部的分格方向分别处理。
3. 在“阅读前准备”中多选缩略图、按页码范围选取，批量设为正文、封面、广告或附页，也可主动将剩余未划分页设为正文。所有页都确认后才能开始，后端同样强制校验。追加页面需重新确认新增部分；确认旧页原有用途不会清空既有进度。
4. 保存划分后默认自动识别作品并联网查背景，可核对来源后采用，或不采用新背景直接开始。也可以仅保存划分。正文按页发送至模型，封面/广告/附页不发送给剧情分析；封面可作为背景识别素材。页面用途由用户确定，模型不会重新判定页面用途，也不因自己的分类把握而暂停；内容拒绝与真正的接口/格式错误仍会暂停。每页完成立即保存，失败后从未完成页继续。
5. 点击关系阶段查看历史图谱，每个阶段显示原导入顺序中的页码范围；漫画明确提供章节或故事时间时一并显示。点击人物查看外貌身份、关系证据及证据页，拖动人物、缩放画布，或切换到“关系工作台”与独立标签页。宽屏详情侧栏可收起，窄屏切换查看，人物档案支持姓名、别名及外观搜索。
6. 自动头像由模型提供位置、服务端从原图裁剪。头像不准确时，点击人物，再选择“从当前页框选头像”，在原图框选后保存。
7. 关系图右上角下载按钮导出整个项目分析 JSON（含页面范围、人物、关系证据及历史阶段；图片仍存本机）。

模型格式偶发异常时先尝试明确、无歧义的本地语法修复（例如对象末尾无值的空字段），仍不合格再自动纠错一次（最多两次 API 请求）。未知时间、空别名及无效的可选头像框可兼容处理；剧情记忆、人物列表、关系变化等关键字段不会用空值代替。纠错仍失败时停在当前页并显示具体字段，已读进度保留。原始异常输出、校验问题和纠错结果保存在对应项目的 `diagnostics/<page-id>.json`，仅留本机、不通过静态文件接口公开，便于定位问题；文件不含 API 密钥或图片请求。

提示词要求客观分析完整剧情，而不是忽略成人情节。对于明确成年人的情节，在允许范围内概括事件事实、意愿证据、动机、后果及关系影响，不因裸露或成人主题直接当作无剧情页面。表达保持分析性、非色情化，不复述露骨过程；性接触不自动等于恋爱、自愿或长期承诺，动作细节不成为关系标签。模型的内容拒绝、`content_filter` 或明确 `blocked` 返回会单独标记为“内容无法处理”并暂停，不触发格式纠错、不伪装成封面广告，也不通过指定正文绕过限制。涉及未成年人或疑似未成年人的性内容不会继续提取；不保证第三方模型会接受所有成年题材页面。

前端在暂停和出错状态也会同步后台进度，切回窗口立即刷新，不再因为旧报错停止状态更新。

阅读暂停或因错误中断时，工作台上方提供“继续分析”入口，从当前待处理页续读，已完成页不会重读。内容无法处理的页面会保留拒绝原因，需先将其排除才会继续。模型接口或格式错误会保留具体错误信息，修正后可直接重试。

更改已阅读页面的顺序、分格方向或用途会使前文理解失效，因此清除原分析后重新阅读；界面会提示。移除尚未阅读的页面不影响已完成的分析，会保留进度。用户导入的源文件不被修改。

## 阅读速度与连续性

普通正文页返回 `memoryMode: delta`，只输出本页新增剧情；长期摘要保存在 `project.memory`，摘要后的逐页增量和未解线索保存在 `project.readingMemory`。两部分共同构成前文，导出分析 JSON 时均保留。旧项目已有的 `memory` 直接作为长期摘要使用，不需要清空进度。

累计 5 个正文增量后的下一张正文要求 `checkpoint` 汇总；增量文字累计达到 6000 字符时也提前要求汇总。汇总整合旧摘要、全部增量和本页事件，成功后清空已整合的增量。重要未解线索独立保存，只能通过模型明确的解决操作移除；没有在某页提及不会删除。广告、封面和附页不推进记忆汇总计数。记忆汇总不会产生新的关系阶段。

新模型输出必须明确记忆模式并提供 `threadChanges`（没有变化时为 `[]`），防止将增量误当完整记忆覆盖前文。格式失败、错误线索引用和内容拒绝均不提交本页，继续分析从最后已保存状态恢复。内部旧格式读取逻辑仍兼容完整记忆，但新 API 请求强制使用明确的模式。

图片准备采用每个阅读任务独立、有界的内存缓存。请求第 N 页时并行准备其参考图和下一张正文图片；第 N+1 页的模型请求仍等待前页校验、应用并保存。预取不调用模型、不生成未来剧情上下文、不额外产生 API 用量，失败不会阻止当前页，取消或任务结束释放缓存。维持原有图片分辨率与质量。

每页计时在已有总耗时、请求数和 Token 用量基础上增加图片/上下文准备耗时、API 耗时、上下文字符数与图片数。界面显示前两项，后两项在项目 JSON 的 `pages[].timing` 中查看。准备耗时是当前页等待准备完成的时间，不包括已与上一页请求重叠的全部后台工作；API 耗时包括各次请求与响应处理。Token 用量包括该次阅读内的修复请求，重试整页后计时仍只保留最近一次阅读的数据。清除分析会一起清除旧计时。

当前采用顺序剧情分析和并行图片准备，未启用多页模型请求并发或多页合批。已有的并发原型会使用尚未包含前页结果的快照，冲突记录不等于剧情理解正确，不能把其加速比视为正式版本保证。实际速度及身份连续性仍需同素材、同模型、同配置的多轮评测。

## 角色档案与状态

“背景与人物”可自动查找背景，也保留手动编辑。AI 从最多两张封面和前两张正文中选最多三张识别标题、署名与人物线索，再调用现有 DeepSeek 密钥对应的 Anthropic Web Search，最多三次搜索，优先官方资料与可靠百科。即使原作名未知，也会用独特章节标题等查询出处。只有无可用线索时留待用户补充；可填写名称线索后重试。

检索结果先保存为草稿，展示原作、识别依据、背景、人物对照与来源链接，用户采用后才进入阅读上下文。来源必须来自此次实际返回的 `web_search_tool_result`；已知跟踪参数与编码差异可规范化，仍不匹配时只自动校正一次，并从真实来源目录选择编号，不会把未联网回答或模型自编 URL 当搜索证据。无法搜索、缺乏来源或结果截断时保留旧背景。背景是原作参考，不直接写成本篇剧情，也不提前更新角色生死/关系。官方搜索能力说明：[DeepSeek Web Search](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/#using-web-search-in-claude-code)。联网检索会产生额外模型用量，自定义兼容服务需要提供相同搜索接口。

模型复用临时人物 ID，后续出现真名时更新原档案并保留旧称呼。新输出 ID 若通过 `sameAs` 给出至少 0.9 的身份匹配置信度和具体依据，会先归到已有 ID，再提交人物、关系、头像和状态。较低把握或两个档案都已经存在的情况，保留为人工核对候选。仅在对白中提及的名字进入单独列表，不生成图节点。每次阅读附上一张已读正文参考；固定外观描述与优先最近出场的最多 8 人参考头像帮助跨页匹配；正文之间夹有广告或附页时仍引用最近已读正文，不发送未来页。全部人物的姓名、别名、外观与当前事实仍在上下文中，非近期人物只省去重复证据。

已有重复人物可在“人物归并”中选择重复档案与保留档案，预览后确认合并。同步更新关系端点、状态目标、别名、阶段图和基线，去掉自身连线；历史阶段只使用当时已有信息。后续模型通过重定向表沿用归并结果。最近一次合并保存本机私有备份，继续阅读或发生其他编辑前可撤销；有后续修改时拒绝覆盖新进度。不会自动批量合并已有项目，也不自动改写旧的逐页阶段。

点击人物卡片打开“角色档案”，或从该标签浏览本阶段全部角色。档案包含简介、别名、身份背景、当前状态和变化/线索记录，每条新事实均附证据与原始页码。图中展示最多两条状态摘要，点击人物可查看全部。

模型按作品选择档案与状态维度，支持生存、健康、行踪及对指定人物的好感、信任、敌意等。态度按人物方向分别记录；没有原作数值时不生成好感分数。未知状态留空，推测标记“待确认”，存疑反向线索保留在记录中，不覆盖已确认事实。相同状态不重复记入历史，明确撤销有记录可查。

一般状态变化更新当前阶段；主线人物明确死亡、复活等重大状态转折可在模型给出持久影响的依据且置信度不低于 0.85 时新增阶段。档案按阶段保存，早期阶段不显示后文状态。

旧项目自动展示已保存的姓名、简介、头像和关系；新结构化档案和状态从后续阅读开始积累，不将旧简介猜测成生死或好感，也不自动重读、清空进度。完整重读可使用现有“清除分析并重新阅读”，会产生 API 用量。

## 阶段规则

- 第一张正文建立初始阶段，此时可以没有关系。
- 以人物 ID、关系维度和方向定位关系；双向关系的端点顺序不影响比较。
- 小变化、新增关系或旁支人物只更新当前阶段的图、人物和结束页码，不单独建图。
- 新阶段必须同时满足：关系数据或已确认的重要状态确实变化，模型明确给出有持久影响的重大转折 `turningPoint`、具体理由和不低于 0.85 的置信度。模型默认返回 `turningPoint: null`，不确定时不切阶段；没有固定每几页分图的规则。
- 提示词使用当前阶段起点、初始关系和累计记忆，判断正式结盟、决裂、身份真相导致的关系重构等质变。证据补充、同义改写、同一场景的连续动作和短暂情绪不作为转折。
- 新阶段深拷贝人物和关系；已结束阶段展示该阶段末尾的状态，不被后文覆盖。当前阶段持续更新，起点关系单独保留以供模型比较。人工修正头像会同步到已有阶段。
- `kind` 是模型产生的稳定关系维度，`label` 是简短的稳定状态；详细事件写在证据和梗概中。阶段判断仍依赖模型语义判断，需要根据证据核对。
- 已有旧版逐页阶段不自动改写。新规则适用于后续阅读和新项目，历史数据保留。

## 文件与验证

- `server/provider.ts`：API 配置、视觉请求和结构校验。
- `server/analysis.ts`：人物归档、关系更新、去重与历史阶段。
- `server/index.ts`：导入、裁剪、后台阅读任务和 API。
- `src/App.tsx` / `src/Graph.tsx`：阅读工作台与可交互关系图。
- `data/projects/<id>/`：本地持久化项目、图片、缩略图和头像；每页结果原子写入 `project.json`。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd audit
```

自动化测试使用隔离临时目录和模拟视觉 API，覆盖真实 HTTP 上传、自然排序、API 请求图片内容、封面广告过滤、关系阶段去重、历史快照、自动裁剪、失败恢复、取消任务、排序后失效、删除未读页保留进度、诊断写入失败不影响页面、错误信息不含本机路径及更换地址不复用旧密钥。模拟模型的测试数据不会出现在实际书架。

`npm.cmd run test:live` 是可选的付费真实接口测试：在隔离临时目录生成一张原创双格漫画，让实际 DeepSeek 模型读取并校验人物与关系。该测试不属于默认离线测试集。人工使用和自动化测试不能替代跨作品识别质量评估；当前尚未完成完整的浏览器视觉与交互验收。

这是面向个人本机的核心版本，服务仅监听 `127.0.0.1`，不是带多用户认证的公网服务。模型判断可能有误，不能保证广告识别或跨页身份匹配百分之百正确；人工页面划分、证据核对和人物归并用于纠错。暂不支持 PDF、压缩包导入、OCR 独立校对或自动合并误认人物。
