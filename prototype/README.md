# 阅读速度实验

`compare.mjs` 是此前的独立实验，不是正式后台任务调度器。保留原实现用于研究；它从当次启动的状态快照并行请求模型，再按页提交。

2026-10-06 对已有本机结果的检查（第 4～12 页，9 页）：

| 指标 | 原串行 | 原 3 路并发 |
| --- | ---: | ---: |
| 总时间 | 444.614 秒 | 156.702 秒 |
| 请求次数 | 10 | 10 |
| 输入 Token | 91,679 | 85,757 |
| 输出 Token（含推理） | 92,237 | 60,945 |
| 推理 Token | 79,182 | 51,039 |
| 使用不完整前文的页数 | 0 | 8 |
| 记忆冲突记录 | 0 | 8 |

原样本加速约 2.84 倍，但没有人工标注的正确答案，不能据此认定理解质量相同。两次运行最终的人物数、关系数也不同。

原型的 `validateWrites` 主要检查写入字段：有些人物和关系冲突会过滤更新；记忆和阶段冲突只是记录，仍返回模型原记忆及阶段建议。缺少前页信息引起的语义误解也不一定表现为字段冲突。因此按顺序提交不足以保证连续性。

正式代码复用了逐页耗时、请求与 Token 统计，新增准备/API 耗时，并发仅用于本地图片准备。模型仍严格顺序读取，记忆使用增量和定期检查点。

注意：原型动态导入当前服务器代码；现在的请求、记忆结构已与上述历史结果不同。原型尚未适配完整的增量记忆冲突检测，不能将新跑出的结果与旧日志直接作为优化前后对照，也不要用其结果覆盖实际项目。运行会调用真实 API 并产生用量，脚本中的默认源项目属于本机实验路径，应改用明确授权的隔离样本。`out/` 含本地漫画派生资料，已排除出 Git。

后续评测应固定同一素材、模型、推理强度与提示词版本，重复多次记录总时间、中位/P95 页耗时、重试率和 Token 用量；另行核对人物重复/误合并、事件遗漏、关系证据和阶段边界。正式优化的加速比目前未测定。
